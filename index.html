02 / How I work

Do the homework.
Make the work count.

I like the puzzle: figuring out what users actually need and what we can realistically deliver.

I might start with Sales feedback, a search trend, a broken symbol, or something I notice while using the product. The starting point changes; the need to understand the problem doesn't.

THE PROBLEM / 01

First, figure out what's actually wrong.

Customer feedback, product searches, existing diagrams, or my own review usually reveal the first clue. I look for the underlying problem instead of rushing to add more content.

03 / Beyond the big releases

The small decisions add up.

Not everything useful is a flagship project. These are a few other examples of product judgment in practice.

01 / PRODUCT ORGANIZATION

Making Azure libraries maintainable

I reorganized Azure icons to follow Microsoft's own categories instead of keeping an ever-growing “New Shapes” library. New releases could then fit into a structure users already recognized.

02 / DISCOVERABILITY

Looking at what people can't find

I use internal search behavior, template usage, Google Search Console, and Keyword Planner to spot gaps and improve titles, organization, and content that customers are trying to find.

03 / SPECIALIST RESEARCH

Building for crime-scene work

Separate from accident reconstruction, I researched forensic reference material to improve dated crime-scene libraries with blood-pattern, evidence, and repositionable scene symbols.
